## Problem Statement

Dependency version migration is painful. Developers know they need to upgrade (Spring Boot 2.7→3.0, Kafka 2.8→3.0, React 17→18, etc.) but the process is:
1. Read the changelog
2. Hunt for breaking changes
3. Manually update config files
4. Hunt down deprecated API calls across the codebase
5. Hope tests pass

No tool guides them interactively, applies the code changes, and validates with their actual test suite. Renovate/Dependabot only bump version numbers. GPT-Migrate is for language migration, not version migration. General AI agents (Aider, Goose, Claude Code) can theoretically do it but have no version-specific migration knowledge.

The position nobody occupies: **guided, version-aware, test-validated migration CLI that works for any stack.**

## What Makes This Cool

The "whoa" moment is NOT code generation. It's when the tool runs your existing tests after applying changes and they PASS.

That's trust. That's the product. Every other AI tool generates code and leaves you wondering if it works. This one proves it.

Secondary cool: it works for private repos, no cloud, no sign-up, your own AI key. It respects the developer's environment.

## Constraints

- Open source, no monetization intent
- 100% local — no backend server, no telemetry, no cloud dependency
- v0.1 supports: Anthropic API key and OpenAI API key. Ollama + Claude Code auth deferred to v0.2.
- TypeScript/Node.js (consistent with existing repo)
- Must work from a service root — the directory where the manifest file lives
- Always show diff + confirm before writing to disk — never silently modify files

## Premises

1. **The existing JSON migration data is the moat.** Reuse `src/data/migration-guides/*.json` as structured AI context fed into the system prompt. This grounds the model and reduces hallucination on breaking changes. The JSON schema (breakingChanges, deprecatedFeatures, codeExamples, configUpdates, documentationLinks) is already well-designed.

2. **100% local, no server.** This is what makes it trustworthy for private repos. Zero dependency on our infra.

3. **Always diff-first.** Show exactly what changes before writing to disk. Trust is the whole product.

## Cross-Model Perspective

Second opinion from Codex (gpt-5.4):

**Coolest version (v2 roadmap):** "prove-it" mode — creates a disposable git worktree, tries multiple migration strategies (recipe, codemod, LLM repair loop), runs tests after each, returns the SMALLEST GREEN DIFF with cited breaking changes. Not "AI suggests edits" — the tool searched for a passing upgrade. *Deferred to v0.2 — not in v0.1 scope.*

**Key insight:** "The rest is support structure." The test validation loop is the core. Everything else (manifest detection, provider abstraction, diff display) is delivery mechanism.

**50% head start considered:** `aider`. Rejected — Python dependency (this repo is TypeScript), unstable API surface, higher user friction, less control over UX.

## Approaches Considered

### Approach A: Vertical Slice
Build one end-to-end command for React 17→18 only. Proof of concept, then expand.
Effort: S (human: ~1 week / CC+gstack: ~2 hrs). Risk: Low.
Rejected: Ships fast but reads as a toy. Full architecture is achievable with CC.

### Approach B: Full CLI Architecture (CHOSEN)
Provider-agnostic CLI with setup wizard, manifest detection, diff+confirm loop, test runner, MIGRATION.md. v0.1 ships React + Spring Boot. v0.2 adds more stacks + providers.
Effort: L (human: ~3 weeks / CC+gstack: ~4 hrs). Risk: Medium.

### Approach C: Aider Wrapper
Rejected: Python dependency, unstable API, user must install aider separately.

## Recommended Approach

**Full CLI Architecture (Approach B)**

```
packages/
  cli/
    src/
      cli.ts                ← entry point, commander
      commands/
        setup.ts            ← AI provider wizard (v0.1: Anthropic + OpenAI)
        migrate.ts          ← core interactive migration flow
        analyze.ts          ← scan manifests, show what's outdated
      detect.ts             ← manifest scanner (package.json, pom.xml, go.mod, etc.)
      guides.ts             ← JSON migration data loader + query
      providers/
        index.ts            ← provider interface: { chat(system, user): Promise<string> }
        anthropic.ts        ← Anthropic API key auth
        openai.ts           ← OpenAI API key (also covers Gemini via OpenAI-compatible endpoint)
      patch/
        react.ts            ← React codemods (ReactDOM.render → createRoot, etc.) — exports patchReact17to18
        springboot.ts       ← javax→jakarta, Security config rewrites — exports patchSpringBoot27to30
        index.ts            ← auto-discovers patchers by convention: any .ts file in patch/ exporting
                               a function named patch{Tech}{From}to{To} is registered automatically.
                               Adding a patcher: create file, export function, restart tool — no code changes needed.
      validate.ts           ← test runner
      report.ts             ← MIGRATION.md generator
      diff.ts               ← diff display + confirm prompt
      config.ts             ← ~/.stack-migrator/config.json (plaintext, user-warned)
  migration-data/           ← JSON files moved from src/data/migration-guides/
  web/                      ← current React app (keep as docs/demo site)
```

**Provider interface:**
```typescript
interface Provider {
  chat(system: string, user: string): Promise<string>;
  name: string;
}
// Each file in providers/ exports a class implementing this.
// Adding a provider: implement interface, add API key prompt to setup.ts.
```

**AI response format (structured JSON):**
```typescript
// The system prompt instructs the AI to respond ONLY in this format.
// Validated with zod before use. On parse failure: abort + show raw AI output + ask user to retry.
interface MigrationPlan {
  files: Array<{
    path: string;       // relative to cwd
    before: string;     // original content snippet or regex to match
    after: string;      // replacement content
    reasoning: string;  // why this change is needed
  }>;
  uncovered: Array<{    // breaking changes from JSON guide that couldn't be auto-patched
    title: string;
    description: string;
    docsUrl: string;
  }>;
}
```

**CLI commands:**
```bash
stack-migrator setup                    # configure AI provider + key
stack-migrator analyze                  # scan manifests, show what's outdated
stack-migrator migrate                  # interactive: pick dep, versions, generate doc, apply, test
stack-migrator migrate react 17 18      # non-interactive shorthand
```

**Core migrate flow:**
```
PRE-FLIGHT:
   - Check for .git/ in cwd or any parent. If git repo: run `git status --porcelain`.
     If output is non-empty (dirty working directory): print "Uncommitted changes detected.
     Run `git stash` first, then re-run stack-migrator." and exit.
   - If no .git/ found: warn "Not a git repo — undo requires manual revert from MIGRATION.md."
     and ask "Continue anyway? (y/n)"

1. Detect manifest in cwd (look for: package.json, pom.xml)
   - If multiple found at same level (e.g., root package.json + subdir pom.xml): list them and
     ask user to choose one. Only operate on chosen manifest's directory.
   - If none found, print "No manifest found in current directory. cd to your service root." and exit
   - v0.1: only package.json (React) and pom.xml (Spring Boot) supported

2. Ask: which dependency to migrate?
   Show only deps with available upgrade paths in migration-data/.
   Version matching: guide files named {tech}-{fromVersion}-{toVersion}.json (e.g. react-17-18.json).
   Only offer version pairs that have a matching guide file or LLM-only fallback.

3. Ask: from version? to version? (filter to paths that have JSON guides)

4. Load matching JSON guide from migration-data/
   - If no guide: warn "No structured guide found — will use LLM-only mode (less reliable)" and continue

5. Detect test command:
   - package.json: read scripts.test. If absent, default "npm test"
   - pom.xml: default "mvn test" (always runs default profile; custom profiles require manual entry)
   - Prompt user to confirm: "Detected test command: 'npm test'. OK? (enter to confirm or type custom command)"
   - Do NOT use `which` to validate — it only checks PATH. Instead: validate by dry-running as part of step 12.
   - If test command exits non-zero at step 12: treat as FAIL regardless of which tests failed.

6. Send to AI:
   System: [full JSON guide as context] + "Respond ONLY as JSON matching MigrationPlan schema."
   User: "Scan these files for patterns from the JSON guide: [list of src files, config files, test files.
         Exclude: node_modules/, build/, dist/, target/, .git/]"

7. Parse AI response as MigrationPlan (zod).
   On first failure: retry with explicit prompt: "Respond ONLY as valid JSON. No markdown code blocks.
   No text outside the JSON object. Schema: { files: [{path, before, after, reasoning}], uncovered: [{title, description, docsUrl}] }"
   On second failure: enter manual mode — open MIGRATION.md in $EDITOR with pre-filled breaking change list.
   User edits the file manually. After save, ask "Apply changes? (y/n)" for any file paths specified in the doc.

8. Apply patches:
   a. Try registered codemod first (patch/react.ts for react:17:18, patch/springboot.ts for springboot:2.7:3.0)
   b. For files not covered by codemod, apply AI-suggested patches from MigrationPlan.files
   c. Both paths require confirmation before writing

9. Generate MIGRATION.md with sections:
   ## Summary: {tech} {fromVersion} → {toVersion} on {date}
   ## Breaking Changes Applied (auto-patched)
   ## Manual TODOs (uncovered[] from MigrationPlan — must fix by hand)
   ## Files Changed (list with brief reasoning)
   ## How to Undo: git checkout -- . or git stash

10. Show unified diff:
    - ≤10 files: show full diff with color
    - >10 files: show summary ("23 files changed, +1,247 -890 lines") then offer: [a] view by file [b] view all [c] skip
    - Ask: "Apply these changes? (y/n/quit)"

11. If yes: write all files to disk

12. Run test command (from step 5):
    - Stream output to terminal in real time
    - Sanitize output before streaming: redact strings matching /(?:apiKey|token|password|secret)=[^\s]+/gi
    - On completion: print PASS or FAIL in bold (based on exit code — non-zero = FAIL)
    - Save full test output to ~/.stack-migrator/migrations/{timestamp}/test.log
    - If FAIL: print last 50 lines of output + "Full log: ~/.stack-migrator/migrations/{timestamp}/test.log"

13. If tests FAIL: offer options:
    a. View the diff you applied (to understand what changed)
    b. Undo changes (git checkout -- .)
    c. Open MIGRATION.md to see Manual TODOs (AI may have missed something)
    d. Keep changes anyway and fix tests manually

    Undo command (only offered if git repo detected in pre-flight):
      "git checkout -- ."
    If no git repo: "Revert manually using MIGRATION.md > 'Files Changed' section."
```

**Error handling:**
```
API failure (timeout, rate limit, network):
  → Retry once after 3 seconds
  → On second failure: save partial state + print "API failed. Run again to retry from checkpoint."

Malformed AI response (not valid JSON):
  → Print raw response + "AI returned unexpected format. Retrying with stricter prompt..."
  → Retry once with explicit format reminder in prompt
  → On second failure: abort + suggest manual mode

Test command not found:
  → Print "Command '{cmd}' not found. Fix your environment and re-run 'stack-migrator migrate' — changes have NOT been applied."
  → Exit without touching files

Manifest not found:
  → Print "No supported manifest found in {cwd}. Run from a service root (where package.json or pom.xml lives)."
  → Exit
```

**v0.1 scope (ship this first):**
- Stacks: React 17→18 and Spring Boot 2.7→3.0 only
- Providers: Anthropic API + OpenAI API only
- Manifests: package.json + pom.xml only
- Monorepo: not supported — must cd to service root, tool exits if multiple manifests found at same level
- Multi-hop: not supported — single version jumps only; MIGRATION.md notes if user must chain
- Config storage: plaintext `~/.stack-migrator/config.json` with warning "API key stored in plaintext at ~/.stack-migrator/config.json"
- Partial coverage: uncovered breaking changes written to MIGRATION.md as Manual TODOs

**v0.2 roadmap (not in v0.1):**
- "prove-it" mode: git worktree + multi-strategy retry loop returning smallest green diff
- Additional providers: Ollama (local), Claude Code auth, Gemini native
- Additional stacks: Kafka, Angular, Node.js, Vue, Elasticsearch
- Monorepo support + multi-hop migrations
- System keychain for API keys

## Decisions Made (resolved open questions)

| Question | Decision |
|---|---|
| Monorepo handling | v0.1: exit with error if multiple manifests found. User must cd to service root. |
| Test command detection | Parse manifest scripts, fallback to stack default, prompt if ambiguous. Validate before use. |
| Partial coverage | Uncovered breaking changes go to MIGRATION.md "Manual TODOs" section. |
| Multi-hop | Not supported in v0.1. MIGRATION.md will note if chaining is needed. |
| Config storage | Plaintext ~/.stack-migrator/config.json with explicit user warning. Keychain in v0.2. |

## Success Criteria (v0.1)

- `npx stack-migrator migrate` works end-to-end from a real React 17 project with a test suite
- `npx stack-migrator migrate` works end-to-end from a real Spring Boot 2.7 project with Maven tests
- Supports Anthropic API key and OpenAI API key
- MIGRATION.md is generated and readable as a PR description
- Test validation prints PASS/FAIL + full log path
- On API failure, tool exits cleanly without corrupting files

## Distribution Plan

- **Primary:** `npx stack-migrator` (no install required for first use)
- **Secondary:** `npm install -g stack-migrator`
- **Package name:** `stack-migrator` on npm
- **CI/CD:** GitHub Actions — on tag push, build and publish to npm

```yaml
# .github/workflows/release.yml
on:
  push:
    tags: ['v*']
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', registry-url: 'https://registry.npmjs.org' }
      - run: npm ci && npm run build
      - run: npm publish
        env: { NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }} }
```
